## Synchronously Download Single File

### Function Name: `download_sync`

??? Docstring

    Downloads a resource synchronously over HTTP2 and writes it safely to a temporary file before atomically moving it to disk.

    !!! Snippet

        ``` docstring
        Download a resource synchronously to a file.

        The response is streamed in chunks and written to a temporary file
        located in the destination directory. Once the download completes
        successfully, the temporary file is atomically moved to the requested
        output path.

        Args:
            url: URL or client-relative path of the resource to download.
            output_path: Destination path for the downloaded file.
            file_suffix: Suffix to use when creating the temporary file.
            client: HTTPX client used to perform the request.

        Raises:
            HTTPStatusError: If the server returns an unsuccessful HTTP status.
            FileNotFoundError: If the destination directory or file cannot be
                accessed.

        Returns:
            None.
        ```

    ``` python
    from os import replace, unlink
    from os.path import dirname
    from tempfile import NamedTemporaryFile
    from time import perf_counter_ns
    from urllib.error import HTTPError

    from httpx import (
        Client,
        HTTPStatusError,
    )
    from httpx._types import HeaderTypes

    def download_sync(
        url: str,
        output_path: str,
        file_suffix: str,
        client: Client,
    ) -> None:
    
        __dirname = dirname(output_path)
        temp_file_name: str
        chunk_count = 0
        total_size = 0

        try:
            with NamedTemporaryFile(
                suffix=file_suffix,
                mode="wb",
                delete=False,
                delete_on_close=False,
                dir=__dirname,
            ) as tmp_file_desc:
                temp_file_name: str = tmp_file_desc.name
                try:
                    with client.stream("GET", url) as response:
                        response.raise_for_status()
                        for chunk in response.iter_bytes(chunk_size=1000 * 256):
                            if not chunk:
                                continue
                            tmp_file_desc.write(chunk)
                            total_size += len(chunk)
                            chunk_count += 1
                    tmp_file_desc.flush()
                    logger.debug("Flushed Tempfile: {}", temp_file_name)
                except (HTTPError, FileNotFoundError, HTTPStatusError) as error:
                    logger.error(error)
                    raise
        except FileNotFoundError as error:
            logger.error(error)
            unlink(temp_file_name)

        replace(temp_file_name, output_path)
    ```

Next we declare a `NamedTemporaryFile` context manager. To the context manager we supply the following:

-   suffix = file_suffix
-   mode = "wb" `write bytes`
-   delete = False
    - We do not want to destroy the temp file after the write operations have completed.
-   delete_on_close = False
    - On Windows, which I am, the documentation says you do not have to supply this field if the former `delete` is False, but we
      include it here to be explicit, don't worry it is ignored anyways for the aforementioned reason.  

Firstly, assign your the name property on the target variable `tmp_file_desc` to your locally-global variable declaration `temp_file_name`.

``` python
temp_file_name: str = tmp_file_desc.name
```

Note that the `NamedTemporaryFile` context manager sits inside a try-catch block where we are catching for a `FileNotFoundError`.
This will become important latter.

Next we implement the standard streaming logic with some additional bonuses. Note at the end we flush the temp file.

``` python
with client.stream("GET", url) as response:
    response.raise_for_status()
    for chunk in response.iter_bytes(chunk_size=1000 * 256):
        if not chunk:
            continue
        tmp_file_desc.write(chunk)
        total_size += len(chunk)
        chunk_count += 1
tmp_file_desc.flush()
```

Next comes the part that may trip some up a bit. Inside the try-catch block the `NamedTemporaryFile` acquires a lock on the opened temp
file. We could copy the temp file to a second file and write that to disk, or we can just rename the file that is already on disk. I chose
to do the latter. But we have to do so outside the try-catch block because only then does `NamedTemporaryFile` release the lock
on the file.

``` python
replace(temp_file_name, output_path)
```

And that is pretty much it, you can add your logging, and timing logic however you want. In my honest opinion that is how you
should download files over HTTP.

## Synchronously Download Many Files

### ThreadPoolExecutor

The second function which is complement to the one above. The question now is, how do we download many files without using asyncio
or some similar library? The answer is, carefully. No not really, it is not that hard.

``` python
def download_all_sync(all_urls: list) -> None:
    """Download multiple resources concurrently using a shared HTTP client.

    Creates a single synchronous HTTPX client and uses a thread pool to
    download all resources in parallel. Each download is delegated to
    ``download_sync``.

    Args:
        all_urls: A list of argument sequences containing the parameters
            required by ``download_sync``, excluding the HTTP client.
            Each element should contain ``url``, ``output_path``, and
            ``file_suffix``.

    Returns:
        None.
    """

    with Client(
        transport=SYNC_TRANSPORT,
        headers=TRANSPORT_HEADERS,
        base_url="https://www.bungie.net",
    ) as client:
        url_list: list[list] = [[*x, client] for x in all_urls]

        with ThreadPoolExecutor(max_workers=20) as executor:
            executor.map(lambda p: download_sync(*p), url_list)
```
